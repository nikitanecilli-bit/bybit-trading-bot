# Навигация по проекту

## Читать в первую очередь
1. `/AGENTS.md` — обязательные инструкции агенту.
2. `/PROJECT_WORKING_RULES_RU.md` — автономность, безопасность и стандарты исследований.
3. `/PROJECT_AUDIT_RU.md` — текущий статус технического аудита.
4. `/EXPERIMENT_LEDGER_RU.md` — журнал проведённых экспериментов (исторический источник результатов).
5. `/TEST_COVERAGE_MATRIX_RU.md` — что проверено и что ещё неизвестно.
6. `/NEXT_RESEARCH_PLAN_RU.md` — порядок дальнейшей работы без повторения тестов.

## Структура текущей ветки
| Путь | Назначение |
|---|---|
| `Bybit_Trading_Engine_v14_research.py` | Основной исследовательский симулятор. Не live-исполнитель. |
| `bybit_downloader.py` | Загрузка публичных рыночных данных. |

| `.github/workflows/` | Повторяемые CI/research workflow. |
| `test_*.py` | Существующие регрессионные тесты (пока в корне). |
| `EXPERIMENT_LEDGER_RU.md` | Канонический журнал экспериментов. |
| `*_REPORT*.md`, `*_report*.md` | Отчёты конкретных исследований. |
| `cryptofetch_*.zip` | Архивы загруженных датасетов; не изменять и не удалять. |
| `Bybit Profit Dashboard*` | Отчётные/визуальные материалы, не часть движка. |

## Принцип наведения порядка
Сначала документация и единая навигация, затем аудит и только после него — физическая реорганизация кода. Файлы не перемещать, пока не проверены ссылки из workflow, импортов, README и исторических инструкций. Это предотвращает поломку воспроизводимости.

## Канонические правила
- Один эксперимент — один ID, одна гипотеза, одна конфигурация и одна запись в журнале.
- Исторические отчёты сохраняются; исправления оформляются отдельной записью, не переписывая прошлое.
- Сырые данные и holdout — immutable.
- Статус CI не равен доказательству прибыльности.
- Положительные результаты всегда читать вместе с издержками, моделью исполнения и отрицательными периодами.
