# Аудит официального Bybit H1-архива BTCUSDT — 2026-11-25

## Цель

Проверить, может ли официальный публичный архив Bybit восстановить известные разрывы в BTCUSDT H1 trade candles без стороннего поставщика и без обхода сетевых ограничений.

## Подтверждённый источник

Каталог: https://public.bybit.com/kline_for_metatrader4/BTCUSDT/

Проверены публичные каталоги:
- 2020: https://public.bybit.com/kline_for_metatrader4/BTCUSDT/2020/ — видны месячные файлы интервала 60 минут с апреля по декабрь 2020.
- 2023: https://public.bybit.com/kline_for_metatrader4/BTCUSDT/2023/ — видны месячные файлы интервала 60 минут за все 12 месяцев.
- 2024: https://public.bybit.com/kline_for_metatrader4/BTCUSDT/2024/ — видны месячные файлы интервала 60 минут с января по ноябрь 2024; декабрь в каталоге не отображается.

Имена файлов имеют вид `BTCUSDT_60_YYYY-MM-01_YYYY-MM-lastday.csv.gz`. Это отдельный архив H1 candles, не каталог ежедневных отдельных сделок `/trading/BTCUSDT/`.

## Значение для текущих разрывов

Ранее нормализованный Bybit H1 archive содержал 4 разрыва:
- 2023-12-09 07:00 — 2024-01-01 00:00 UTC;
- 2024-01-09 07:00 — 2024-02-01 00:00 UTC;
- 2024-02-17 15:00 — 2024-03-01 00:00 UTC;
- 2024-03-09 07:00 — 2024-04-01 00:00 UTC.

Каталог H1-архива содержит месячные файлы для каждого из этих месяцев. Следовательно, источник является конкретным кандидатом на восстановление всех четырёх разрывов. Это пока подтверждение наличия файлов в каталоге, а не подтверждение корректности их содержимого или совпадения временных меток.

## Существующий загрузчик

В ветке есть:
- `scripts/download_bybit_btcusdt_public_history.py`;
- `.github/workflows/download-bybit-btcusdt-public-history.yml`.

Загрузчик использует официальный домен `public.bybit.com`, месячные CSV.GZ-файлы интервала 60 минут, сохраняет исходные CSV, нормализованный `trade_h1.csv`, SHA-256 и `manifest.json`.

Важные ограничения текущей реализации:
1. В manifest отдельно перечисляются `months_missing`; наличие итогового CSV не означает полное покрытие. Для приёмки требуется нулевой список отсутствующих месяцев в целевом диапазоне и проверка точной H1-сетки.
2. Парсер сдвигает время MT4 на UTC-3 часа. Это преобразование должно быть подтверждено сравнением с уже имеющимися Bybit UTC candles на перекрывающемся интервале до объединения архивов.
3. Необходимо проверить заголовок/схему, OHLC consistency, объём, дубликаты, сортировку, границы месяцев и хеши исходных файлов.
4. Каталоги 2025 и 2026 в рамках этого аудита не подтверждены. Не считать источник полным для всего интервала исследования.
5. Наличие H1 trade candles не закрывает Funding, Mark Price, dated instrument specs, risk tiers или lifecycle gates.

## Решение

- Принять этот каталог как официальный Bybit-only кандидат для восстановления H1 trade candles.
- Не объединять данные автоматически и не запускать PnL.
- Следующий минимальный эксперимент: скачать только месяцы 2023-12 и 2024-01 через существующий загрузчик или ограниченный probe, подтвердить UTC alignment на overlap, затем проверить покрытие четырёх разрывов.
- Если время не совпадает с Bybit UTC grid либо схема/данные не проходят проверки, отклонить архив как источник для текущего loader.
- API HTTP 403 не обходить. Публичный static archive host — отдельный официальный путь, его доступность проверять напрямую без прокси и без приватных ключей.
