# H1 selection code-provenance audit — 2026-11-04

Branch: `research/market-regime-v1-main`  
Scope: train-only Top-5 selection manifest and shared-capital H1 validation runner  
Status: **FIXED — EXACT REPLAY DEPENDENCY SET ENFORCED**  
Market PnL replay: **NOT RUN**

## Finding

Before this correction, `validate_selection_provenance()` checked the hashes and sizes of every code file already listed in the frozen selection manifest. It did not require the current replay dependency list to contain exactly the same paths.

Consequently, if a new replay-critical dependency was added after Top-5 selection, the old manifest could pass: all previously recorded files remained unchanged, while the new dependency was not represented in the manifest. This was a confirmed provenance-validation gap. It could allow a replay to run with a dependency set different from the one used to freeze the selected universe.

## Correction

In `scripts/run_h1_shared_capital_portfolio_validation.py`, `validate_selection_provenance()` now:

1. Strictly validates each recorded/current code provenance row (`path`, `sha256`, non-negative integer `size_bytes`).
2. Rejects duplicate dependency paths in either list.
3. Requires exact equality between the recorded and current dependency path sets.
4. Reports missing and newly added dependencies and requires the train-only selector to be rerun.
5. Compares SHA-256 and file size for every path after exact-set validation.

This is fail-closed. It does not change signal generation, position sizing, execution, costs, portfolio risk, or production defaults.

## Additional paired-result integrity finding — 2026-11-04

A second fail-closed gap was found in `build_paired_donchian48_comparison()`: unlike the EMA pair builder, it compared shared portfolio invariants with `dict.get()`. If an invariant such as `test_start_ts` were absent from all three result rows, all three lookups returned `None` and the pair could still be emitted. This did not alter the replay, but it weakened the guarantee attached to the comparison summary.

The builder now requires every invariant to be present and non-null in the D20 control row and present/non-null/equal in both D48 arms. Missing metadata raises `ValueError` before any paired delta is produced.

## Additional transitive-import dependency finding — 2026-11-04

A follow-up static import audit found that the exact-set guard still depended on a manually maintained seed list. The Top-5 selector imports `scripts.snapshot_bybit_linear_universe`, which in turn imports `scripts.snapshot_bybit_instruments`; the latter was absent from `H1_REPLAY_CODE_PATHS`. Therefore the exact-set comparison could pass while a transitive local Python dependency was not hashed.

Correction:
- Added recursive AST-based discovery of repository-local Python imports, including nested package imports and transitive dependencies.
- Both the train-only selector and H1 validation now build code provenance from the same resolved dependency closure.
- Required seed files fail closed if missing or syntactically invalid.
- Added regression tests proving the previously omitted Bybit instrument module is captured and a synthetic nested import chain is resolved.

This closes the identified static local-import omission. Dynamic imports, runtime-loaded plugins, external package versions, interpreter/environment differences and workflow-level behavior are separate provenance dimensions and are not claimed to be covered by Python import closure alone. No market PnL was run.
