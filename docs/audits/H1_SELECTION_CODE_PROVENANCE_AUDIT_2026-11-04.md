Market PnL replay: **NOT RUN**

## Finding

Before this correction, `validate_selection_provenance()` checked the hashes and sizes of every code file already listed in the frozen selection manifest. It did not require the current replay dependency list to contain exactly the same paths.

Consequently, if a new replay-critical dependency was added after Top-5 selection, the old manifest could pass: all previously recorded files remained unchanged, while the new dependency was not represented in the manifest. This was a confirmed provenance-validation gap. It could allow a replay to run with a dependency set different from the one used to freeze the selected universe.

## Correction

In `scripts/run_h1_shared_capital_portfolio_validation.py`, `validate_selection_provenance()` now:

1. Strictly validates each recorded/current code provenance row (`path`, `sha256`, non-negative integer `size_bytes`).
2. Rejects duplicate dependency paths in either list.
3. Requires exact equality between the recorded and current dependency path sets.
4. Reports missing and newly added dependencies and requires the train-only selector to be rerun.
5. Compares SHA-256 and file size for every path after exact-set validation.

This is fail-closed. It does not change signal generation, position sizing, execution, costs, portfolio risk, or production defaults.

## Decision

The exact dependency-set provenance gap is closed in the research branch. Any existing selection manifest produced before a replay dependency-set change must be regenerated by the train-only selector; it must not be reused across code revisions.
