# H1 Top-5 selector — per-symbol train/validation leakage audit (2026-11-04)

## Verdict

**Confirmed selector defect; fixed before any Bybit-native selection manifest or market PnL run was created.**

File: `scripts/select_h1_top5_train_only.py`  
Function: `select_train_only()`  
Regression: `tests/test_h1_top5_selector.py::test_candidate_training_slice_rejects_short_symbol_validation_leakage`

## Defect mechanism

The selector derived one calendar cutoff from the longest archived symbol, then clipped every candidate at that same timestamp. That does not guarantee a train-only slice for shorter histories: a short symbol's own 50% boundary can occur much earlier than the longest-symbol cutoff. Its second-half candles could therefore influence candidate ranking.

Concrete deterministic example used in regression coverage:

- Longest reference history: 10,000 H1 bars, indexed 0–9,999.
- Shared cutoff: index 4,998 (one-bar embargo before the reference validation fold).
- Short candidate history: 4,000 H1 bars, indexed 0–3,999.
- Candidate's own first validation timestamp: index 2,000.
- Old logic would include the short candidate through index 3,999, crossing its own validation boundary by 1,999 bars.

The former post-selection overlap check only guarded the selected primary/reserve baskets. It did not prevent leaked candidates from influencing the ranking before the primary basket was chosen.

## Correction

- Added `candidate_training_slice()`, which computes each symbol's own first-validation timestamp from its complete archived history.
- The shared calendar cutoff is now applied only if the resulting per-symbol training slice ends strictly before that symbol's own validation boundary.
- Candidates that cross their own boundary are excluded with reason `candidate_training_overlaps_own_validation`; the manifest records the candidate validation timestamp and relevant cutoff/coverage evidence.
- The candidate-specific validation boundary is also included in each scored candidate row.
- Existing common-timestamp intersection, minimum history, lifecycle, and selected-basket checks remain in place.

## Impact and limits

- This was a **future selection integrity defect**, not a correction to previously reported strategy PnL. The repository currently has no `data/research/h1_top5_selection/` output or frozen Bybit Top-5 selection manifest; the Bybit-native archive gate has not been met.
- No Bybit API, private account connection, new market-data download, strategy PnL replay, paper trading, or live order was run.
- The fix prevents this specific per-symbol temporal leakage. It does not solve survivorship bias from missing historical delisted contracts, temporary listing/trading suspensions, or missing point-in-time universe history.
- The current CryptoFetch archive remains development-only and is not promoted to an untouched holdout.

## Decision

Keep the Top-5 selector blocked until the required data inputs exist. When selection eventually becomes permissible, rerun it from scratch on the final frozen code and inputs; do not reuse any manifest generated by earlier selector code.
