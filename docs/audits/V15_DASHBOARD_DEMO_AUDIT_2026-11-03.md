# Аудит Bybit Profit Dashboard v15 — демо, не торговый backtest

Дата: 2026-11-03  
Объект: `dashboards/v15/Bybit Profit Dashboard v15 (Чистый HTML).html` и встроенная копия в инструкции скачивания.  
Статус: **UNVALIDATED DEMO / НЕ ИСПОЛЬЗОВАТЬ ДЛЯ ОЦЕНКИ PnL, РИСКА ИЛИ ГОТОВНОСТИ К LIVE**.

## Краткий вывод

Этот HTML — самостоятельный JavaScript-прототип. Он не импортирует Python engine, не читает `TradeRecord`, не загружает engine journal и не использует H1 shared-capital runner. Его KPI нельзя считать результатами текущего Bybit research engine.

В исходном интерфейсе присутствовали утверждения «Чистый Профит», «прибыльный бэктест», «Почему бот теперь в плюсе» и «Комиссии снижены на 96%». Код не подтверждал эти заявления. В текущем PR интерфейс маркирован как DEMO, а ложные утверждения удалены. Расчётная логика намеренно не переписывалась.

## Подтверждённые проблемы модели

1. **Offline candles содержат planted edge.** `generateCalibratedCandles()` использует детерминированную генерацию и направленный drift для выбранных символов (`hasEdge`, `edgeStrength`, `trendLeft`). Это искусственно заложенное преимущество, а не исторические Bybit данные.
2. **Live API не делает модель валидной.** `fetchBybitLive()` загружает H1 candles, но последующий расчёт выполняет отдельная JS-стратегия `runSwingV15()`, а не Python engine. При сетевой ошибке отдельный символ незаметно переключался на synthetic fallback; теперь статус явно сообщает, что синтетика использована.
3. **Нет shared-capital portfolio.** Каждый вызов `runSwingV15(sym, candles)` начинает с `eq = CAPITAL` (10 000 USDT) независимо от остальных символов. Затем `portTrades.push(...tr)` объединяет сделки отдельных виртуальных счетов, а `calcStats(portTrades)` считает их как будто это один портфель с начальным капиталом 10 000 USDT. Одновременная потребность в капитале, общий риск-бюджет, max positions и порядок исполнения между символами не моделируются. Portfolio return и Max DD в таком виде невалидны как shared-capital метрики.
4. **Selection bias.** Инструмент включается в портфель, если `st.net > 0 && st.pf >= 1.15`, после оценки его на том же массиве свечей, который используется для отчёта. Это отбор по результатам оцениваемой выборки, не независимый holdout.
5. **Отдельная, не сверенная стратегия.** JS-модель задаёт собственные lookback/EMA, entry/stop/TP, cooldown, risk sizing и trade management. Совпадение с Python engine не установлено. Сделки не экспортируются из engine и не имеют exchange execution provenance.
6. **Упрощённые издержки и исполнение.** Fee/slippage зашиты константами в JS; нет funding, dated instrument specs, qtyStep/minNotional, risk tiers, margin/liquidation, spread, queue priority, partial fills, latency или adverse selection. Maker fill нельзя вывести из касания OHLC.
7. **Внутрисвечные допущения не проверены.** На свече входа модель не обрабатывает позицию до следующей итерации, поэтому экстремумы fill-bar не проходят полный stop/TP lifecycle. TP1/TP2 path и break-even последовательность не подтверждены независимым движком.
8. **Нет аудируемого data manifest.** Не сохраняются исходный dataset hash, точный диапазон/coverage, версия кода и параметры источника в формате, сопоставимом с research artifacts.

## Что изменено в этом PR

- В верхнюю часть HTML добавлено постоянное предупреждение о synthetic planted edge, отдельной JS-модели, независимых per-symbol счетах, selection bias и fallback.
- Переименованы заголовок, режим offline, кнопка запуска и KPI labels: они явно относятся к DEMO, а не к engine.
- Удалено неподтверждённое заявление о снижении комиссий на 96%, а также «чистый профит» и утверждения, что робот уже прибыльный.
- При fallback на synthetic данные статус явно указывает на это.
- Инструкция скачивания получила предупреждение перед встроенной копией HTML.
- Расчётная логика не менялась: цель PR — предотвратить ошибочное использование артефакта, не выдавая косметическую маркировку за исправление модели.

## Остаточные ограничения

- PDF-экспорт в `dashboards/v15/` — отдельный исторический артефакт; его бинарное содержимое этим PR не изменяется. Его следует считать архивным/невалидированным, пока он отдельно не проверен и не снабжён таким же предупреждением.
- Даже после предупреждений HTML остаётся демонстрационным калькулятором. Для реального PnL использовать только versioned engine + official data + shared-capital replay + immutable artifacts.
- Не переносить его метрики в experiment ledger, не использовать для выбора top-5 symbols и не считать подтверждением 20% monthly target.

## Решение

**REJECT as profitability evidence. KEEP only as clearly labelled demo artifact.**  
Не запускать его показатели в сравнении стратегий и не использовать для решений о капитале или live trading.
