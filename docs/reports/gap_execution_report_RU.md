# Микрозадача № 3 — исполнение заявки при гэпе

## Область проверки
Проверена только функция `_try_fill_pending()` в исследовательской копии `Bybit_Trading_Engine_v14_research.py`. Рабочая версия не изменялась.

## Фактическое поведение кода
- Рыночный вход: если разница между ценой открытия следующей свечи и `entry_price` больше `max_chase_limit_pct`, заявка отменяется и позиция не открывается.
- Рыночный вход в пределах порога: исполнение моделируется по `curr.open`, а не по исходной цене сигнала.
- Лимитная покупка: если `curr.low <= ref`, считается исполненной. Цена задаётся как `min(ref, curr.open)`, поэтому гэп вниз моделируется по открытию (лучше лимитной цены), а если открытие выше лимита, но свеча коснулась лимита — по лимитной цене.
- Лимитная покупка, не коснувшаяся уровня, отменяется без позиции.

## Вывод и ограничения
В проверенных сценариях рыночный вход не получает искусственно выгодную цену сигнала: он либо отменяется при гэпе выше порога, либо исполняется по открытию следующей свечи. Лимитный вход моделируется по лимитной цене или по более выгодному открытию при гэпе через лимит.

Это узкие синтетические тесты одной функции, а не подтверждение корректности всей модели исполнения. Не проверялись короткие лимитные заявки, граничное значение ровно на пороге, проскальзывание на входе, частичные исполнения, стакан/ликвидность и реальные исполнения Bybit. В частности, рыночный вход в этом бэктесте использует `curr.open`; заложенное в расчёт размера позиции проскальзывание не означает, что цена входа фактически сдвинута на величину `TAKER_SLIP`.
