# Разбор новой подборки гипотез пробойного робота

Дата: 2026-11-04
Источник: загруженный пользователем `MASTERPROMPT_breakout_bot.md`.
Статус: **HYPOTHESIS BACKLOG / NOT APPROVED / NO PNL RUN**.

## 1. Краткий вывод

В исходнике есть полезный набор гипотез и правильные требования к качеству бэктеста. Но это не готовая спецификация текущего робота: файл описывает более раннюю архитектуру v6.1, 15m основной сигнал, H-1 breakout + H-2 mean reversion, OI и набор фильтров, которых нет в текущей замороженной H1 исследовательской конфигурации.

Поэтому идеи перенесены в этот реестр с пометками о пересечениях и статусах. Не копировать исходник целиком в корень как `AGENTS.md`, `CLAUDE.md` или `.cursorrules`: это создало бы конфликт с актуальными правилами проекта, H1-приоритетом, действующим data gate и пользовательским запретом подключать Bybit до прибыльных backtests и paper trading.

Ни одна идея из файла не считается проверенной только потому, что она логична. Старые 15m параметры и значения v6.1 не переносятся автоматически в H1.

## 2. Что в исходнике полезно

- Причинность: сигнал по закрытой свече, исполнение не раньше следующего бара; HTF только по закрывшемуся HTF бару.
- Консервативная OHLC последовательность: если внутри свечи возможны stop и TP, учитывать adverse outcome; gap через stop — по open; не считать касание лимита гарантированным fill.
- Раздельная проверка last/mark, funding, контрактных шагов, минимального notional и dated risk tiers.
- Фиксированные даты, hash provenance, запрет тихой деградации при пропусках.
- Одна гипотеза — одно изменение; критерии записывать до открытия результата; отрицательные результаты сохранять.
- Разделение Explore/Confirm/untouched holdout; учитывать число испытанных вариантов.
- Предпочтение улучшений исполнения, выходов и риск-менеджмента вместо бесконечного добавления индикаторов.

Большая часть этих принципов уже отражена в актуальных `AGENTS.md`, `PROJECT_WORKING_RULES_RU.md`, experiment template и текущем research plan. Не нужно дублировать их вторым противоречащим набором инструкций.

## 4. Поздние идеи из исходника

| Идея | Пересечение / статус |
|---|---|
| Подтверждение 4h и уровни прошлого дня/недели | Новая структурная гипотеза; пока не приоритетнее закрытия базового H1 edge/data gates |
| Taker buy/sell, ликвидации | Требуют новых point-in-time данных; отложить, не симулировать из OHLCV |
| Relative strength между монетами | H-A уже отклонена на исследованных folds; не возвращать подбором рангов/порогов |
| Добор на ретесте | Отдельная execution/risk гипотеза; не смешивать с Donchian48+EMA |
| Адаптивный trailing | Пересекается с оценкой exits; только после MAE/MFE и корректной cost model |
| Basis / OI / funding skew | OI timestamp semantics ранее вызывали сомнения; funding completeness gate открыт. Не использовать до подтверждения источника/тайминга |
| Разные long/short параметры | В текущем Top-5 pipeline есть directional-scope ограничения; не расширять до валидного point-in-time universe и парного протокола |
| Макро/листинги/unlocks | Нужны датированные исторические события без look-ahead, низкий приоритет |
| ML meta-classifier | Отложить: текущая выборка и число независимых событий недостаточны; риск leakage/multiple testing высокий |
| Модель проскальзывания по стакану | Полезная будущая инфраструктура, но требует L2/quote/trade данных; OHLC limit-touch нельзя считать реальным maker fill |

## 5. Приоритетный backlog

Порядок отражает полезность и отсутствие прямого дублирования, а не обещание провести тест немедленно.

1. **HYP-BRK-02 — breakout ATR buffer.** После закрытия data/accounting gate: один frozen буфер, парный baseline, shared-capital, заранее выбранные folds; соседние значения — только в Explore, Confirm не перенастраивать.
2. **HYP-RISK-09 — correlated directional exposure cap.** Сначала специфицировать точный расчёт корреляции/направленного gross risk без будущих данных; затем одна paired ablation против текущего portfolio risk cap.
3. **HYP-EXEC-06 — conservative retest/maker execution.** Не «вероятность fill на глаз», а заранее заданные сценарии: queue haircut, spread, partial fills, timeout/cancel, adverse selection. До quote/trade evidence — стресс-модель, не факт исполнения.
4. **HYP-EXIT-05 — exit policy from MAE/MFE.** Только после зафиксированного entry signal и достоверного ledger; не подбирать stop/TP на использованных folds.
5. **HYP-TIME-07 — session/time-of-day.** Только после Funding/Mark completeness; заранее определить календарь сессий и не выбирать окна по тому же Confirm.
6. **HYP-CTX-08 — BTC/broad context.** Не повторять E12/E13; новая гипотеза должна отвечать на конкретную проблему fold-to-fold instability и сохранять локальные альт-сигналы.

H3, H4, H-A relative strength и H-C invalidation не ставить в очередь на повтор в исходной формулировке: по ним уже есть неактивный gate или отрицательный результат.

## 6. Протокол для всех будущих кандидатов

- Сначала закрыть текущий Bybit-native data/accounting gate; до этого никаких новых market PnL runs на уже использованных CryptoFetch folds.
- У каждого кандидата отдельная карточка с ID, экономическим механизмом, одной переменной, параметрами, датами, universe, критерием отказа, числом сравнений и code SHA.
- Использовать causal completed-bar features; next-bar execution; exact timestamp HTF joins.
- Отчитывать net expectancy, net PnL, PF, DD, turnover, trade count, fees, slippage, funding, fill/expiry, per-symbol и per-fold; shared-capital replay обязателен.
- Стрессовать costs и fill model. OHLC limit-touch — optimistic proxy, не реальный maker fill.
- Не открывать lockbox для выбора параметров; один раз использовать Confirm. Любая настройка после Confirm расходует его.
- Никакой API/account connection до устойчиво прибыльных backtests и прибыльного paper/forward этапа — согласно `PROJECT_WORKING_RULES_RU.md`.
