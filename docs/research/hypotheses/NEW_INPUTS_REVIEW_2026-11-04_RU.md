## 1. Решение по расположению

Исходники скопированы без смыслового редактирования в `docs/research/hypothesis_inputs/`. Ветка `main` оставлена нетронутой. Этот файл — индекс и аналитическая сортировка; он не превращает предложения в одобренные изменения стратегии.

- `RECOMMENDATIONS_and_top10_mistakes-1.md` — расширенная версия; считать основной методологической версией.
- `RECOMMENDATIONS_and_top10_mistakes.md` — краткая версия первых трёх частей; сохранить как короткую памятку, не считать независимым источником дополнительных гипотез.
- `breakout_filters_master_prompt_1h.md` — отдельный H1-набор фильтров, не смешивать с прежним `MASTERPROMPT_breakout_bot.md` v6.1/15m, который уже разобран в `MASTERPROMPT_BREAKOUT_HYPOTHESIS_REVIEW_RU.md`.
- `Гипотезы_пользователя_2026-11-03.md` — ранее загруженный базовый backlog из 10 направлений; включён рядом для целостности исходных материалов.

## 2. Главные выводы

1. Новые файлы полезны как каталог идей и методика проверки, но **ни один не является доказательством edge**.
2. H1-фильтры содержат несколько идей, которые уже проверялись в близкой форме. Повторять прежние варианты без нового причинного механизма, новой спецификации или независимых данных нельзя.
3. Самые полезные дополнения — предварительный event study, явный учёт числа попыток, механические проверки prefix-invariance/future mutation и отдельная структурная гипотеза качества уровня.
4. Текущий Donchian48/EMA50/EMA200 эксперимент уже имеет frozen preregistration и paired arms. Новые фильтры нельзя добавлять в него: это уничтожит причинную интерпретацию трёхстороннего сравнения.
5. Все рыночные PnL-тесты остаются заблокированы до закрытия Bybit-native data/accounting gate.

## 4. Разбор рекомендаций и top-10 ошибок

### Принять как правила исследовательского процесса

- **Event study до полного backtest.** Для сигнала измерять forward returns через 1/4/16/64 бара в ATR units, сравнивать с unconditional и random-entry baseline, использовать block bootstrap по дням и сравнивать raw edge с круговыми издержками. Это предварительный screening, не замена полноценному replay: stop/TP и path-dependent execution меняют распределение.
- **Trial accounting.** Записывать все проверенные варианты и неудачные попытки; число попыток должно быть известно до Confirm. В текущем проекте есть ledger и preregistration, но автоматический полный подсчёт N_trials по каждому семейству не подтверждён.
- **Механические anti-lookahead тесты.** Prefix-invariance, мутация будущих данных, точные timestamp joins и causal completed-bar features. Существующие тесты закрывают отдельные случаи, но каждый новый feature должен получать собственную проверку.
- **Статистика зависимых сделок.** Предпочитать R, block bootstrap по времени и интервалы; не трактовать большое число сделок как независимую выборку.
- **Реалистичное исполнение.** Не считать касание лимита fill; учитывать spread, queue, partial fills, latency, timeout и adverse selection.
- **Разделение одной переменной.** Не объединять вход, фильтр, stop/TP и sizing в один эксперимент.

### Уже частично отражено в проекте

- Cost stress 1.0x/1.5x/2.0x уже зафиксирован в H1 Donchian48/EMA preregistration.
- Shared-capital portfolio risk и ограничение числа позиций уже присутствуют; отдельный directional/correlation cap остаётся HYP-RISK-09.
- Funding/Mark, point-in-time specs, lifecycle, accounting reconciliation и lookahead gates уже вынесены в отдельные технические блокеры.
- Paper/forward и мониторинг дрейфа — более поздние ворота, не задача текущего этапа.

### Не принимать как готовые числовые законы

- 2–3 года истории, 100 сделок, Sharpe > 3, RVOL 1.5, compression percentile 20–35%, 3–4 фильтра и любые другие числа из исходников — ориентиры/эвристики. Они требуют обоснования и фиксации до просмотра результата.
- «Если сырой edge не найден, никакие стопы/тейки не помогут» — полезная эвристика для screening, но не строгая теорема: execution и payoff design могут менять распределение результата. Использовать event study как ранний фильтр, не как окончательный вердикт.

## 5. Сортировка кандидатов по дальнейшему действию

| Приоритет | Кандидат / работа | Статус | Следующее допустимое действие |
|---|---|---|---|
| P0 | Event-study screening для уже замороженного сигнала | Методологический пробел; данных пока недостаточно | Подготовить спецификацию и тесты на synthetic fixtures; market data run только после gate |
| P0 | Trial count / N_trials в реестре | Процессный пробел | Вести число вариантов и причин отказа в карточке/ledger; не открывать новые sweep |
| P1 | Seasonal RVOL как альтернатива volume ratio | Новый вариант, не проверен на H1 | После data gate — одна заранее заданная paired ablation |
| P1 | Structural level quality (touches + prior highs/lows) | Новый кандидат | Сначала causal level definition + event study; отдельно от EMA/volume |
| P2 | 4h/1D HTF context | Похож на EMA gate, но не эквивалентен | Только после результата текущей EMA ablation |
| P2 | Session/news calendar | Частично исследовано; news history отсутствует | Сначала point-in-time calendar/data audit |
| P2 | OI / taker delta / liquidations | Data-dependent | Только после архивов и timestamp audit |
| P3 | L2/iceberg/spoofing | Исторических данных нет | Не включать в backtest backlog; отдельная future collection idea |

Порядок P0 означает подготовку методологии, а не запуск рыночного PnL. Все рыночные эксперименты остаются за data gate.

## 6. Что не переносить в текущую стратегию

- Не добавлять все фильтры из master-prompt как единый набор.
- Не менять frozen D20/D48/D48+EMA paired experiment.
- Не повторять E13 compression/BTC context, H-A relative strength или H-C post-break invalidation на прежних folds.
- Не использовать 15m параметры как будто они уже валидированы для H1.
- Не считать OHLC limit-touch реальным maker fill.
- Не создавать новый alpha ID для уже существующих HYP-EXEC-06, HYP-RISK-09, HYP-TIME-07, HYP-CTX-08.
- Не считать источники, формулировки или числовые пороги подтверждёнными результатами.
